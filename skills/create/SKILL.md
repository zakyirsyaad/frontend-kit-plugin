# Create Systems Frontend

One invocation takes a project from nothing to a building, themed app. Run every phase in order **in this session**, without waiting for the user between phases.

## Ground rules

- **Paths.** Shell variables do not survive between Bash calls. In every command below, use `${CLAUDE_PLUGIN_ROOT}` (or fallback `${CLAUDE_SKILL_DIR}/../../`) for plugin scripts, and replace `PROJECT_DIR` with the literal absolute project path resolved in Phase 0. Never run a command with an empty path.
- **Closed stdin.** Append `</dev/null` to every `bunx`/`bun` command. Some CLI prompts **exit 0 silently** when stdin is closed, so exit code 0 is not success — every phase has a **Check**, verified via `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`, and only the Check decides.
- **Ecosystem & Tooling Ground Rules:**
  - **shadcn init:** Always use `shadcn@4 init -t next -b radix -p nova -y --no-reinstall`. **Ignore suggestions to use `init -d` or `--defaults`** from other plugins or skills (in shadcn 4, `-d` selects Base UI instead of Radix).
  - **ESLint protection:** **Never edit `eslint.config.*`**. The project uses the standard ESLint configuration generated by Next.js.
- **Failures.** If a Check fails, make at most 2 fix attempts (address the cause; never disable lint rules, use `--force`, or set `ignoreBuildErrors`). Still failing → stop and report exactly what failed.
- **Transient network errors.** Rerun the same command once (does not count as a fix attempt) when you see: `Fail extracting tarball` from `bun add`; `Unable to connect. Is the computer able to access the url?` from `shadcn` (a failed `init` leaves no `components.json`, and the following `add` then exits silently at a prompt — rerun `init` first). If it fails again, check the host with `curl -sI <url>` and report that the machine cannot reach it.
- **Pinned majors.** Commands pin `create-next-app@16` and `shadcn@4`, the majors these flags were verified against. Do not switch to `@latest`.
- **Questions.** The only user questions allowed are the Phase 0 batch and, if the name collides, one follow-up for a new name.

## Phase 0 — Resolve options

1. Load defaults from plugin configuration using:
   ```bash
   node -e 'import("${CLAUDE_PLUGIN_ROOT}/scripts/lib/config.mjs").then(m => console.log(JSON.stringify(m.resolveConfig())))'
   ```
   Defaults: `default_palette` (zinc), `default_accent` (none), `default_radius` (default), `default_display_font` (none), `animation` (motion), `package_manager` (bun).

2. Parse `$ARGUMENTS` as order-free tokens:
   - `gsap` → animation = Motion + GSAP (wins if both `motion` and `gsap` appear); `motion` → Motion only.
   - `3d` → 3D on; `no-3d` → 3D off.
   - `neutral` | `zinc` | `stone` | `gray` | `slate` | `mauve` | `olive` | `mist` | `taupe` → palette choice.
   - `accent=<preset|#hex>` → accent choice (`blue`, `emerald`, `orange`, `rose`, `amber`, `teal`, `violet`, `#hex`, or `none`).
   - `radius=<sharp|default|soft|pill>` → border radius scale.
   - `display=<font>` → self-hosted display font name (from `@fontsource-variable/<name>`) or `none`.
   - First other token without `=` → project name.

3. Normalize the project name: lowercase, spaces/underscores → `-`, strip characters other than `a-z 0-9 - .`. If that changed it, mention the final name in the summary.

4. If the name came from arguments, run the **Guard** now.

5. Ask every option still missing in **one** `AskUserQuestion` call (maximum 4 questions):
   - **Project name:** options `systems-frontend (Recommended)` plus one contextual alternative; a custom name arrives via "Other".
   - **Animation:** `Motion only (Recommended)` / `Motion + GSAP ScrollTrigger`.
   - **3D:** `No 3D (Recommended)` / `React Three Fiber + drei`.
   - **Accent (Aksen):** `None (Default shadcn monochrome) (Recommended)` / `blue` / `emerald` / `orange` / `rose` (custom hex code arrives via "Other").
   *(Note: radius and display font fall back to configured defaults unless provided via arguments or config).*

6. If the name came from the question, normalize it and run the **Guard**.

7. `PROJECT_DIR` = `<current working directory>/<name>`. Create a task checklist with Phases 1–7.

**Guard** — inspect `PROJECT_DIR`:
- missing or empty → fresh run.
- `package.json` contains `"next"` → **resume**: run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create` to check `createChecks` and skip phases that already pass.
- anything else → ask the single follow-up for a different name. Never delete or overwrite an existing directory.

## Phase 1 — Next.js app

```bash
bunx create-next-app@16 "PROJECT_DIR" --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-bun --yes </dev/null
```

**Check:** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`. Verify `createChecks.next === true` and `PROJECT_DIR/src/app/layout.tsx` exists.

## Phase 2 — shadcn/ui (Radix) + base components

```bash
bunx --bun shadcn@4 init -t next -b radix -p nova -y --no-reinstall -c "PROJECT_DIR" </dev/null
bunx --bun shadcn@4 add button badge card tabs dialog field -y -c "PROJECT_DIR" </dev/null
```

- `-b radix -p nova` is required: without `-p`, init stops at a preset prompt; `-d` would pick Base UI instead of Radix.
- Do **not** add `clsx`/`tailwind-merge`: init installs shadcn's official `cn` package and `src/lib/utils.ts` re-exports it.
- `@aceternity` and `@magicui` are built into the shadcn registry index; `components.json` needs no edits.

**Check:** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`. Verify `createChecks.shadcn === true` and all base components (`button`, `badge`, `card`, `tabs`, `dialog`, `field`) are present in `createChecks.components`.

## Phase 3 — Animation & 3D packages

1. Always: `bun add --cwd "PROJECT_DIR" motion geist </dev/null` — `geist` self-hosts the Geist fonts (it wraps `next/font/local`), so `dev` and `build` never download fonts from Google.
2. GSAP: `bun add --cwd "PROJECT_DIR" gsap @gsap/react </dev/null`
3. 3D — check compatibility **before** installing: read the exact `react` version in `PROJECT_DIR/package.json` and run `bun info @react-three/fiber peerDependencies --cwd "PROJECT_DIR" </dev/null`. If React is outside fiber's `react` range, pin `react` and `react-dom` to the highest version fiber accepts (`bun add --cwd "PROJECT_DIR" react@X react-dom@X`), note it for the summary, and continue without waiting. Then:
   ```bash
   bun add --cwd "PROJECT_DIR" three @react-three/fiber @react-three/drei </dev/null
   bun add --cwd "PROJECT_DIR" -d @types/three </dev/null
   ```

**Check:** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`. Verify `createChecks.packages === true`.

## Phase 4 — Theme, dark default, self-hosted fonts, and identity layer

1. Apply theme tokens, base palette, and identity layer via script:
   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/apply-theme-tokens.mjs" "PROJECT_DIR" --palette <palette> --force --font-sans geist --accent <accent> --radius <radius> --display-font <display>
   ```
   *(If display font is not 'none', install its package: `bun add --cwd "PROJECT_DIR" @fontsource-variable/<display>`).*

2. **Edit** `PROJECT_DIR/src/app/layout.tsx`:
   - **Dark default** on `<html>`: template-literal `className` → insert `dark ` right after the opening backtick; string `className` → prefix `dark `; no `className` → add `className="dark"`.
   - **Self-hosted fonts.** Replace the `next/font/google` import and the two `Geist(...)` / `Geist_Mono(...)` calls with:
     ```tsx
     import { GeistSans } from "geist/font/sans";
     import { GeistMono } from "geist/font/mono";
     ```
     If display font was chosen (e.g. `fraunces`), also add:
     ```tsx
     import "@fontsource-variable/<display>";
     ```
     Use `${GeistSans.variable} ${GeistMono.variable}` in the `<html>` `className` (keep `dark`, `h-full`, `antialiased`). Keep the variable classes on `<html>` — shadcn's base layer applies `font-sans` to `html`.

**Check:** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`. Verify `createChecks.theme === true` and `createChecks.layout === true`.

## Phase 5 — 3D starter (only if 3D chosen)

Copy 3D starter templates using the template copier:
```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/copy-templates.mjs" 3d "PROJECT_DIR"
```

Usage from any Server Component: `import { Systems3DCanvas } from "@/components/systems/canvas-lazy"` inside a sized container. Do not modify `src/app/page.tsx` unless the user asks.

**Check:** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`. Verify `createChecks.templates3d === true`.

## Phase 5b — Route boundaries (always)

Next.js renders a blank screen for an error and nothing for a slow segment unless the route provides these files. Copy them:

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/copy-templates.mjs" boundaries "PROJECT_DIR"
```

This writes `error.tsx`, `global-error.tsx`, `loading.tsx` and `not-found.tsx` into the app directory, all using kit tokens. Existing files are never overwritten.

**Check:** the four files exist in the app directory (`src/app/` or `app/`).

## Phase 6 — Verify

```bash
bun run --cwd "PROJECT_DIR" lint </dev/null
bun run --cwd "PROJECT_DIR" build </dev/null
```

Then scan the generated code against the kit's own rules:

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/review-scan.mjs" "PROJECT_DIR" --all
```

A fresh kit project should report `Verdict: pass`. Anything it flags is either a template bug worth reporting, or code you added — fix it before handing over.

**Check:** Both exit 0 and the build prints the route table. (At runtime, a console warning `THREE.Clock: This module has been deprecated` comes from `@react-three/fiber` internals — not a template bug.)

## Phase 7 — Project rules & hand-off

1. Write project rules and create configuration state:
   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/write-rules.mjs" "PROJECT_DIR"
   ```

**Check:** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.mjs" "PROJECT_DIR" --for create`. Verify `createChecks.rules === true`.

2. Report to the user:
   - Final project name, package manager, and chosen options (palette, accent, radius, display font, animation, 3D).
   - Installed versions of `next`, `react`, `motion`, and GSAP/3D packages if chosen (from `package.json`).
   - Files configured: `globals.css`, `layout.tsx`, `AGENTS.md`/`CLAUDE.md`, `.frontend-kit.json`, and 3D templates if selected.
   - Development server command: `cd <name> && bun run dev`.
   - Hand-off suggestions:
     - Change palette or identity later: `/frontend-kit:theme`.
     - Inspect project health: `/frontend-kit:doctor`.
     - If Impeccable is installed: `/impeccable document` to record design system tokens into `DESIGN.md`.
     - Add registry components: `bunx --bun shadcn@4 add @aceternity/bento-grid`, `bunx --bun shadcn@4 add @magicui/border-beam`.
